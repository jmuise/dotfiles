# Global instructions

- Do not add AI-attribution or promotional lines to any artifact you produce, unless the user explicitly asks for it in that request. This covers — but is not limited to — `Co-Authored-By: Claude ...` trailers in git commits, "Generated with Claude Code" footers and links to claude.com in pull request descriptions, issue bodies, code comments, and documentation. The rule is about the artifact, not the medium: if a human will read it as part of the work, it carries no advertisement. Attribution belongs in the conversation, not in the repository.
- For engineering work that spans multiple components/files in a non-mechanical way, that genuinely needs an independent review before being called done, or that's expected to run longer than a single sitting or produce multiple PRs — delegate to the `number-one` orchestrator subagent rather than doing the decomposition, implementation, and self-review directly in the main session. `number-one` tracks the work, delegates to worker subagents, and keeps implementation separate from review by construction. This does not apply to single-file changes, mechanical/repetitive edits, read-only investigation/lookups, or work the user is actively iterating on turn-by-turn — handle those directly in the main session. The user can always explicitly ask for `number-one` regardless of scope.
